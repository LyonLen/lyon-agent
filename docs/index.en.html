An agent that
learns to get better

lyon-agent is a coding agent that runs in your terminal. Beyond normal chat, tool calls and a fullscreen workbench, it ships an evolution mechanism: production scoring, closed-book exams, task routing, knowledge coverage gates, mechanical workflows — making "the more you use it, the better it gets" a measurable fact, not a slogan.

#Core capabilities

Six pieces form the full loop: run tasks → keep an audit → score → exam → route → freeze workflows.

🖥️

Fullscreen TUI workbench

Streaming transcript, strict thinking fold, approval overlay, image preview; the side steps panel records every tool execution, and alt+e opens the evolution panel. Input queues while busy, slash commands leave a trace, /lang switches Chinese/English; /resume restores steps and usage stats in full.

cmd/lyon · bubbletea
📊

Production scoring & leaderboard

Every model is scored on four dimensions — correctness, efficiency, cost, compliance (weights 0.50 / 0.20 / 0.15 / 0.15) — into a local leaderboard. On-duty means qualified: fail the bar and you are demoted, someone else steps in.

pkg/eval
📝

Closed-book exams

Every 10 rounds triggers a closed-book exam with answer keys. Two consecutive fails vacate the seat, and the next production scorecard re-elects — elimination, coded.

/exam · LYON_EXAM
🧭

Task routing

Tasks are classified first, then dispatched by capability profiles plus a cached recommendation table. Repeated requests converge into a stable routing network with a single entry.

pkg/routing
🧪

Knowledge coverage gate

Before working open-book, take a closed-book quiz on the knowledge coverage; below 0.6 the misses become gaps and the gap-specific material is folded into the task — the gate feeds, it never blocks. You only "know it" once you've proven it.

coverage ≥ 0.6
⚙️

Mechanical workflow execution

Control flow is data, not prompt text: a workflow freezes only through a passing closed-book exam, then steps run mechanically in fixed order and the LLM only fills in each node — no more decide-as-you-go jitter.

/flow · pkg/flow

#Quick start

Zero dependencies (build with Go ≥ 1.25 and run), both Anthropic and OpenAI-compatible endpoints supported.

1 · Build

# from the repository root
go build -o bin/lyon   ./cmd/lyon      # terminal main program (CLI + fullscreen TUI)
go build -o bin/lyond  ./cmd/lyond     # OpenAI-compatible gateway (optional)

2 · Credentials

# Anthropic official
$ export ANTHROPIC_AUTH_TOKEN=sk-ant-...

# or any OpenAI-compatible endpoint (configure key + base URL)
$ export ANTHROPIC_BASE_URL=https://token-plan-cn.xiaomimimo.com/v1
$ export ANTHROPIC_AUTH_TOKEN=<your-key>

3 · Launch

$ ./bin/lyon chat            # fullscreen TUI workbench
$ ./bin/lyon run "refactor this function"  # one-shot CLI, run and go
$ ./bin/lyon chat -c         # sessions auto-save; /resume or -c picks them up anytime
Everything stays local: sessions, leaderboards and exam records all live in $LYON_HOME (default ~/.lyon). No telemetry; memory cloud sync stays off until you explicitly configure LYON_SYNC_URL/TOKEN, and only the team and personal layers sync — the project layer never leaves this machine.
