An agent that
learns to get better

lyon-agent is an AI coding agent that runs on your machine: the Go daemon lyond handles model access, tool execution and the session event stream, while a React workbench in the browser is the main interface. Beyond chat and tool calls it ships an evolution mechanism: production scoring, closed-book exams, task routing, knowledge coverage gates and mechanical workflows — making "the more you use it, the better it gets" a measurable fact, not a slogan.

#Core capabilities

Half a pleasant workbench, half an execution system that evolves on its own.

🖥️

Web workbench

React + Vite frontend: streaming transcript, markdown rendering with a code-block copy button, colored tool output, folded thinking, produced-files card; panes tile freely and the layout persists per session.

web/ · React + connect-es
🗂️

Session workspaces

Every session picks its own workspace (local directory or git clone); tools, files, memory and the repo map all follow. The sidebar groups by workspace with click-to-fold, a git repository badge, two-click delete and one-click saved-snapshot restore.

x-lyon-workspace
🛡️

Approval cards & modes

Risky actions ask as cards that say why and highlight the matched span; approve(y) / deny(n) / always(a) decide in one click, plan interceptions can allow a single file. Four modes — default / plan / bypass / mindmap — cycled with shift+tab.

ApprovalService
🧠

Live mind map

The conversation grows a real-time understanding map in a pane beside chat; ctrl+wheel zooms, middle-drag pans, and editing the map feeds back as a follow-up — a second input channel, not just a view.

pkg/mindmap
📊

Evolution mechanics

Production scoring, closed-book exams, task routing, knowledge coverage gates, mechanical workflows: runs leave evidence, evidence becomes scores, scores decide who works; reliable procedures freeze into data and the LLM only fills in each node.

pkg/evolve · pkg/eval · pkg/flow
⚡

Concurrent sessions

Run many sessions side by side — messages queue while busy and can be interrupted anytime; the sidebar shows running / queued badges, the footer keeps context usage and spend resident.

#Quick start

One Go daemon plus one frontend dev server — the browser is the workbench.

1 · Build

# repository root (Go ≥ 1.25 required)
go build -o bin/lyond  ./cmd/lyond    # daemon: sessions / tools / approvals / gateway

# frontend (dev server with hot reload; production build: npm run build)
$ cd web && npm install && npm run dev   # → http://localhost:5183

2 · Credentials

# Anthropic official
$ export ANTHROPIC_AUTH_TOKEN=sk-ant-...

# or any OpenAI-compatible endpoint (key + base URL together)
$ export ANTHROPIC_BASE_URL=https://token-plan-cn.xiaomimimo.com/v1
$ export ANTHROPIC_AUTH_TOKEN=<your-key>

3 · Launch

$ ./bin/lyond -addr 127.0.0.1:8080 -workspace .   # daemon (the frontend dev server proxies to 8080)
$ open http://localhost:5183                        # the browser is the workbench
Everything stays local: sessions, leaderboards, exam records and memory all live in $LYON_HOME (default ~/.lyon). No telemetry; memory cloud sync stays off until you explicitly configure LYON_SYNC_URL/TOKEN, and only the team and personal layers sync — the project layer never leaves this machine.
