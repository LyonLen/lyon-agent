1 ·快速上手

两条命令构建，一行配置凭证，三种运行方式按场景挑。

构建

# 仓库根目录（需要 Go ≥ 1.25，无其他依赖）
go build -o bin/lyon   ./cmd/lyon     # 终端主程序：CLI + 全屏 TUI
go build -o bin/lyond  ./cmd/lyond    # 可选：OpenAI 兼容网关 / SSE 服务

凭证（二选一）

# A · Anthropic 官方端点
$ export ANTHROPIC_AUTH_TOKEN=sk-ant-...

# B · OpenAI 兼容端点（同一个 key 即可，注意保留 /v1）
$ export ANTHROPIC_BASE_URL=https://token-plan-cn.xiaomimimo.com/v1
$ export ANTHROPIC_AUTH_TOKEN=<your-key>

三种运行方式

命令形态适用场景
lyon run "任务" 一次性执行 脚本/管道里跑完即退，可 -stats 打用量报表；stdin 关闭时审批自动拒绝（fail closed）
lyon chat 全屏 TUI 日常主入口：流式转录 + 右侧步骤面板 + 审批浮层；退出自动存档
lyon chat -c 恢复续聊 重启后接着上次的对话（转录重放、turn 编号延续、步骤面板原样恢复） 
$ ./bin/lyon chat                # 进 TUI，第一次 prompt 会自动注入本地记忆
$ ./bin/lyon chat -c            # 换个终端窗口继续同一份会话
$ ./bin/lyon tools              # 列出全部工具（run_shell/read_file/…）
存储根：一切状态（会话、榜单、考核、workflow）都在 $LYON_HOME，默认 ~/.lyon。 想隔离就在启动前改这个变量——测试、容器、CI 都靠它不碰真实 home。

2 ·界面导览

lyon chat 的全屏工作区分成四块，各司其职。

① 转录区（左，可滚动）

只放问题、模型回答与调用活动：工具行、 [turn N] 回合计数（含 token 用量与 stop 原因）、 📦 compaction、审批与回滚审计。 markdown-lite 高亮、代码块着色、CJK 自动换行。 thinking 按块分组，流式期间实时显示，下一个非思考内容一到就折成 ▸ thinking · N lines 一行，ctrl+t 全局展开/收起。 滚离底部即停止跟随，滚回底部自动恢复。

② 输入行（底）

单行输入，跟随滚动。enter 发送； / 开头走本地命令并弹出候选层（↑↓ 选、回车执行高亮项、tab 补全、esc 关闭）； 唯一匹配的前缀直接执行（/st → /stats）。 @路径 引用工作区图片随消息发送，alt+v 直接把剪贴板里的截图存成 .lyon/paste/ 下的文件并填好 @路径，↑/↓ 空闲时回忆输入历史。

③ 临时输出区（转录下方，── output ──）

指令说明与查询结果（/help /stats /model /sessions 等）渲染在这里， 最多 10 行、超出截断；新 prompt、esc、下一条指令都会清空—— 永远只显示最新一次回答，聊天区不被查询结果刷屏。

④ 步骤审计面板（右）

每一次工具执行一行：序号、名称、耗时、状态，进行中的转圈、失败的标红； alt+↑/↓ 选步、alt+enter 展开完整操作、 alt+←/→ 调宽（28–72 列）。 迭代预算耗尽时，被跳过的步骤如实标 over budget 而不是伪装成失败。 面板本身随会话持久化：存档时步骤列表（含每步耗时）写进快照， /resume 或 -c 恢复后原样回来， 当时正在跑的行会诚实地关成 interrupted。

审批浮层：chat 交互式默认在状态行弹 y/n（-approve=false 关）。 y 一次放行 · a 本会话该工具全部放行 （长任务不被同一问题打断十次）· n 拒绝（超时/关窗一律拒绝，fail closed；拒绝不持久化）。

4 ·演化机制

这是 lyon 区别于「一次性聊天工具」的核心：跑任务留证据、证据变分数、 分数决定上岗、考核守住能力、路由把任务送给最会的、门禁与冻结把可靠的部分固化成机械流程。 四层代码： pkg/eval pkg/routing pkg/models pkg/flow。设计文档见 docs/design/agent-evolution.md。

  1. 生产评分 → 在岗榜单每一次真实运行都会变成一张记分卡。
  2. 闭卷考核 → 淘汰机制每 10 轮考一次，连挂 2 次撤职。
  3. 任务分类 → 推荐路由把下一类任务交给证据最好的 Agent。
  4. 知识覆盖率门禁开卷之前先证明「学过了」。
  5. workflow 冻结 → 机械执行可靠的部分固化成数据，LLM 只做节点内填空。

4.1 · 生产评分与在岗榜单

eval.ScoreWith 按四个维度打分： Correctness / Efficiency / Cost / Compliance 加权出 Total， DefaultThresholds 要求四维全过才 Passed—— 在岗的必须都是达标的。榜单写在 $LYON_HOME/leaderboard.json， 按任务类（coding / fix / review / research / writing / design / data / general）分别记账， 每个 Agent 保留最近 50 张记分卡；每来一张新卡就重新推选 on-duty（证据最新且达标的当选）。 普通 prompt 跑完自动入榜：无标准答案时由盲评裁判打分 （一次低价调用给出 0–1 的 correctness，TUI 后台判分、lyon run 收尾入账， LYON_SCORE=off 可关），判分失败不入账——宁缺毋滥。 lyon run -flow 的流程结果以 source=flow 入榜， correctness 直接取节点通过率。

4.2 · 闭卷考核（每 10 轮）

手写题库 8 个任务类各 4 题，随二进制冻结分发——绝不由被考核的生产任务生成， 首次使用落盘 $LYON_HOME/exams/<class>.json，可检查、可改。 闭卷 = 无工具、不读文件，只考权重里的知识；单题答案期望串命中或关键词过半即得分， DefaultExamPass = 0.75（4 题过 3）。 时钟：每 10 次成功 prompt 记一轮，到点且席位有人时自动开考； 连挂 2 次 → 撤职，席位空缺，下一张生产记分卡重新选举。 考核异步跑在步骤面板里，不打断你手头的活；失败自动归纳错因。

4.3 · 任务分类与推荐路由

routing.Classify 用中英双语关键词计分给任务归类 （同分保留靠前者：fix → review → research → design → coding → writing → data → general）， Openness(text) 给任务打 0–5 开放度。 推荐表 $LYON_HOME/routing.json 对每个 (class, agent) 记运行均值分， 置信度按 mean × samples / (samples + 3) 计算—— 样本越多置信越高，新玩家要靠真实分数挣位置。 pkg/models 注册表 32 个模型全部标注 Reasoning / LongHaul / Openness / Speed / Thrift 五维 0–5 画像。 /route <文本> 会把任务开放度与模型画像对比， 开放度超过画像时提示换将，并附 workflow 匹配建议。

4.4 · 知识覆盖率门禁

开卷干活之前先两段闭卷测验：GenSystem 从任务生成可核对的 Q/A 清单 → BookSystem 盲答 → 对照评分； 低于 CoverageThreshold = 0.6 算缺口， 缺口行（问题 → 期望答案）拼进任务正文定向注入， flow 里经 {{input}} 进入每个节点的 prompt。 门禁本身出错只记 gate skipped，永不阻断。 入口：lyon run -coverage（打印得分）、 lyon run -flow 默认挂门（LYON_FLOW_GATE=off 关）、 /flow save 强制过门且把缺口烙进节点。

4.5 · workflow 冻结与机械执行

控制流是数据，不是提示词。 Workflow{slug, title, trigger, nodes} 的节点有明确的退出判据 （always / command / 退出码 / contains 标记 / judge 窄问）和失败策略 （retry 默认，诊断回灌后有界重试 ≤3 / abort / continue / goto，tick 预算杀死死循环）。 状态机选节点、判出口、限重试——LLM 只做节点内填空（{{input}}），不决定控制流， 「走一步决定一步」的抖动不复存在。 内置 4 条随二进制分发：feature-dev bugfix code-review release； 用户文件 $LYON_HOME/workflows/*.json 按 slug 覆盖内置。

冻结入口 /flow save <slug>： 把本会话的 prompt 组序列化为节点，前置两道门——该任务类闭卷考核通过 + 覆盖率门禁（缺口烙入）——才落盘。 执行入口 lyon run -flow <slug> "任务"： gate → 节点循环（收模型输出、跑 command 判据、窄 judge、诊断回灌）→ 结果打分入榜 + 进推荐表 → 非全过退出码 1。失败的 prompt 异步跑 SummarizeFailure， 产出可核对条件 + patch，面板显示、audit 留痕。

6 ·常见问题

设了迭代预算后，为什么跑到几十次 API 调用就停了，还要回车继续？

那是迭代预算在保护你：设了 -max-iter 或 LYON_MAX_ITER（正整数）时，单个 prompt 最多发那么多次 API 调用（MaxIterations，防跑飞、防刷 token）。 默认不设上限（MaxIterations=0）： ReAct 轮次一路跑到模型自己收工，或 esc 中断为止。

到顶时转录会打印黄色的 ⚡ budget reached — 50 API calls · pending tools skipped, enter to continue，同时系统通知；被跳过的步骤在右侧面板 诚实地标 over budget 而不是伪装成失败。

按 enter 发任意一条消息即可从断点继续——历史已自动修复 （悬空的 tool_use 会补上 synthetic tool_result），不会坏。 顶太紧就调大（-max-iter 100 / LYON_MAX_ITER=100）或干脆不设该变量。

/resume 之后步骤面板和 [turn N] 标记会不会丢？

不会。步骤面板（含每步耗时）随会话快照一起存盘，resume 后原样恢复—— 当时还在跑的行会诚实地关成 interrupted； [turn N] 回合计数按快照里的轮次统计重放，编号延续不重置。 老版本存的快照没有步骤数据，恢复后按新会话从头记（兼容降级，不会报错）。 另外 /new 会把当前对话归档、清空面板——新会话就是干净的。

考核、门禁会不会在我不注意的时候卡死流程？

不会，设计原则是永不阻断：覆盖率门禁自身出错只记 gate skipped；lyon run -exam 考挂只警告、照常执行；闭卷考核异步跑在步骤面板里，不打断正在进行的 prompt。 完全不想被自动考核打扰就设 LYON_EXAM=off。

数据存在哪里？会不会上传到云？

全部在本地 $LYON_HOME（默认 ~/.lyon）： 会话存档、leaderboard、考核题库、routing 推荐表、workflow。 无遥测。只有显式配置了 LYON_SYNC_URL/TOKEN 才会同步记忆。

怎么接 OpenAI 兼容端点？

两种等价方式：设 ANTHROPIC_BASE_URL 指向兼容网关 （协议按 Anthropic Messages 解析），或用 -openai-base https://host/v1 / LYON_OPENAI_BASE 走内置的 OpenAI 协议翻译层。key 与官方一致复用即可。 也可以本地起 lyond 网关反代。

中断（esc / ctrl+c）之后为什么还能继续聊？

中断会触发历史修复：给悬空的 tool_use 合成一个 tool_result，让下一次请求合法。 这也是迭代预算到顶时的收尾机制——所以「停了」不等于「坏了」， 输入任何消息都能接着来。

上下文太大被压缩了，之前的内容去哪了？

单轮用量超过 0.7×200k（-compact-threshold）触发客户端压缩： 历史渲染成带角色标签的文本、发一次独立摘要请求，再用单条摘要消息整体替换历史。 转录里显示 📦 compaction，/stats 里对应 stop=compaction 轮； compact 前有检查点，/rollback 可以退回去。
