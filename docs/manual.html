1 ·快速上手

一条命令构建守护进程，一条命令起前端，浏览器打开就是工作台。

构建

# 仓库根目录（需要 Go ≥ 1.25）
go build -o bin/lyond  ./cmd/lyond    # 守护进程：会话 / 工具 / 审批 / 网关

# 前端 dev server（热更新；生产构建 npm run build）
$ cd web && npm install && npm run dev   # → http://localhost:5183

凭证（二选一）

# A · Anthropic 官方端点
$ export ANTHROPIC_AUTH_TOKEN=sk-ant-...

# B · OpenAI 兼容端点（同一个 key 即可，注意保留 /v1）
$ export ANTHROPIC_BASE_URL=https://token-plan-cn.xiaomimimo.com/v1
$ export ANTHROPIC_AUTH_TOKEN=<your-key>

启动

$ ./bin/lyond -addr 127.0.0.1:8080 -workspace .
# 浏览器打开 http://localhost:5183 —— 前端 dev server 同源代理到 8080，
# bearer token 随请求头自动带上，不需要手工配。
存储根：一切状态（会话草稿、榜单、考核、workflow、记忆）都在 $LYON_HOME，默认 ~/.lyon。 想隔离就在启动前改这个变量——测试、容器、 CI 都靠它不碰真实 home。

2 ·界面导览

工作台四块：会话侧栏（左）、聊天区（中）、 平铺面板（右侧与四周自由分割）、底栏（常驻状态）。 面板布局随会话保存，切会话各自恢复。

① 会话侧栏

顶部 + new session 打开工作区选择器 （像 VS Code 欢迎页：当前目录 / 浏览文件夹 / 从 git clone / 最近列表）—— 每个会话自选工作区，工具、文件、记忆、repomap 全部跟随该目录。 会话按工作区分组：组头点击折叠/展开该组全部会话， git 仓库的组亮 git 徽章； 行内显示模式、running / queued 徽章与最近活跃时间。 删除是两次点击确认（× → 确认?，3 秒不点自愈）。 底部 saved 区是历史会话快照，点一下即恢复成可继续的会话。

② 聊天区

流式转录：问题、模型回答、工具调用卡片与审批卡片。 markdown 全量渲染——代码块悬停出现 copy 按钮， 工具输出按 exit code 与关键词着色； thinking 流式期间实时显示，随后严格折叠成一行， ctrl+o 一键展开/收起全部折叠块。 每轮结束注入一张产出文件卡片（本 run 新写/改动的文件，差分口径，不误伤并行会话写过的路径）。 忙时继续输入不会丢：回车把消息排队，下一轮工具执行前插入间隙合并送达； 侧栏行同步亮 queued 计数。

③ 平铺面板

面板可左右上下自由分割，同一类面板可以开多个，布局随会话持久化：

面板干什么
steps步骤审计：每次工具执行一行（名称 / 耗时 / 状态），进行中转圈、失败标红
files工作区文件树 + SCM 页签（git 状态、diff、暂存操作）
preview文件预览与代码编辑（markdown / 图片 / Office / xlsx / diff…）
terminal工作区内嵌终端
plan计划面板：todo_write 的可读步骤计划
mindmap实时心智图（见下）
memory项目记忆浏览：热层开关、忘记条目
settings引擎与模型：当前模型卡、网关 /models 表、环境变量清单
evolve演化面板（只读）：席位、考试时钟、榜单、路由表、题库、冻结流程

顶部可切换 dashboard 视图（任务执行统计面板）。 心智图与聊天平级：ctrl+wheel 缩放、 中键拖拽平移；选 mindmap 模式时图在前，图上编辑会回流成一条追问推进对话。

④ 底栏

左侧模式芯片：点击展开选择器，shift+tab 循环 default → plan → bypass（mindmap 从选择器或 /mindmap 进）； 中间是常驻提示 / for commands · shift+tab mode · ↑ history 与模型按钮（点击直达 settings 面板，带 👁 表示该模型支持图片输入）； 右下角是上下文仪表：HP 条按占用变色（绿 < 20% ≤ 琥珀 ≤ 70% < 软红）， 右侧跟花费。

审批卡片：shell / 写文件等操作以卡片询问，卡上写明 「为什么问」（匹配 …）并高亮命中的输入片段； 三颗按钮 approve(y) · deny(n) · always(a)（a = 本会话该工具全部放行）。 plan 模式的拦截卡换成策略词汇：按文件放行 f / 切 default d / 切 bypass b / 拒绝 n。 键盘 y n a 直接应答（不占输入框）。

4 ·演化机制

这是 lyon 区别于「一次性聊天工具」的核心：跑任务留证据、证据变分数、 分数决定上岗、考核守住能力、路由记录谁最会、门禁与冻结把可靠的部分固化成机械流程。 演化循环下沉在 pkg/evolve，由 lyond 在每次 prompt_end 挂钩驱动——web 会话与任何入口跑的是同一套循环。 设计文档见 docs/design/agent-evolution.md。

  1. 生产评分 → 在岗榜单每一次真实运行都会变成一张记分卡。
  2. 闭卷考核 → 淘汰机制每 10 轮考一次，连挂 2 次撤职。
  3. 任务分类 → 推荐路由把任务归类，证据进推荐表。
  4. 知识覆盖率门禁开卷之前先证明「学过了」。
  5. workflow 冻结 → 机械执行可靠的部分固化成数据，LLM 只做节点内填空。

4.1 · 生产评分与在岗榜单

eval.ScoreWith 按四个维度打分： Correctness / Efficiency / Cost / Compliance 加权出 Total， DefaultThresholds 要求四维全过才 Passed—— 在岗的必须都是达标的。榜单写在 $LYON_HOME/leaderboard.json， 按任务类（coding / fix / review / research / writing / design / data / general）分别记账， 每个 Agent 保留最近 50 张记分卡；每来一张新卡就重新推选 on-duty（证据最新且达标的当选）。 普通 prompt 跑完自动入榜：无标准答案时由盲评裁判打分 （一次低价调用给出 0–1 的 correctness，引擎在 prompt 结束后异步入账， LYON_SCORE=off 可关），判分失败不入账——宁缺毋滥。

4.2 · 闭卷考核（每 10 轮）

手写题库 8 个任务类各 4 题，随二进制冻结分发——绝不由被考核的生产任务生成， 首次使用落盘 $LYON_HOME/exams/<class>.json，可检查、可改。 闭卷 = 无工具、不读文件，只考权重里的知识；单题答案期望串命中或关键词过半即得分， DefaultExamPass = 0.75（4 题过 3）。 时钟：每 10 次成功 prompt 记一轮，到点且席位有人时自动开考； 连挂 2 次 → 撤职，席位空缺，下一张生产记分卡重新选举。 考核异步执行、不打断进行中的 prompt；考试时钟与题库在 evolve 面板可查， LYON_EXAM=off 可关（轮次照记）。

4.3 · 任务分类与推荐路由

routing.Classify 用中英双语关键词计分给任务归类 （同分保留靠前者：fix → review → research → design → coding → writing → data → general）， Openness(text) 给任务打 0–5 开放度。 推荐表 $LYON_HOME/routing.json 对每个 (class, agent) 记运行均值分， 置信度按 mean × samples / (samples + 3) 计算—— 样本越多置信越高，新玩家要靠真实分数挣位置。 pkg/models 注册表 32 个模型全部标注 Reasoning / LongHaul / Openness / Speed / Thrift 五维 0–5 画像。 分类、榜单与推荐表在 evolve 面板的 /route 分区直接可读。

4.4 · 知识覆盖率门禁

开卷干活之前先两段闭卷测验：GenSystem 从任务生成可核对的 Q/A 清单 → BookSystem 盲答 → 对照评分； 低于 CoverageThreshold = 0.6 算缺口， 缺口行（问题 → 期望答案）拼进任务正文定向注入。 实现在 pkg/eval/coverage.go， 与执行器的接线在 pkg/flow/glue.go（NewGate / NewDiagnose）。 设计原则是永不阻断：门禁自身出错只记 gate skipped，绝不拦下任务。

4.5 · workflow 冻结与机械执行

控制流是数据，不是提示词。 Workflow{slug, title, trigger, nodes} 的节点有明确的退出判据 （always / command / 退出码 / contains 标记 / judge 窄问）和失败策略 （retry 默认，诊断回灌后有界重试 ≤3 / abort / continue / goto，tick 预算杀死死循环）。 状态机选节点、判出口、限重试——LLM 只做节点内填空（{{input}}），不决定控制流， 「走一步决定一步」的抖动不复存在。 内置 4 条随二进制分发：feature-dev bugfix code-review release； 用户文件 $LYON_HOME/workflows/*.json 按 slug 覆盖内置。

会话里的执行入口是 agent 的 flow 工具 （三个动作：list 列冻结清单 · run 按名参执行一串已固化的步骤 · freeze 把刚验证成功的步骤序列存成 slug）—— 模型自己就能以一次调用代替重新推导整套命令序列。 冻结的流程、固化时钟与执行痕迹都持久化在 $LYON_HOME， evolve 面板的 /flow 分区可查。

历史实跑验证（2026-10-12 19:12 → 10-13 06:34，11 小时 21 分）： 整夜驱动 224 轮全部成功退出（0 失败），平均约 3 分钟/轮； 20 场闭卷考核 18 PASS / 2 FAIL——在岗模型连挂两场即被降级， 席位由生产证据重新选举（被驱逐者不自动回位）； 206 次盲评入榜、得分 0.80–1.00 确有区分度； bugfix 流程 18 连绿自动固化，终局路由表 fix 类 100 样本 / 置信 0.96。 这套机制的原始驱动脚本随旧版演示一并下线，产物仍可在 $LYON_HOME 里复盘。

6 ·常见问题

设了迭代预算后，为什么跑到几十次 API 调用就停了？

那是迭代预算在保护你：设了 -max-iter 或 LYON_MAX_ITER（正整数）时，单个 prompt 最多发那么多次 API 调用（防跑飞、防刷 token）。 默认不设上限：ReAct 轮次一路跑到模型自己收工，或你点打断为止。

到顶时会话里会出现 budget reached 提示； 被跳过的步骤在 steps 面板诚实地标 over budget 而不是伪装成失败。

再发任意一条消息即可从断点继续——历史已自动修复 （悬空的 tool_use 会补上 synthetic tool_result），不会坏。 顶太紧就调大（LYON_MAX_ITER=100）或干脆不设。

切会话、刷新页面之后转录和步骤还在吗？

在。转录与步骤由服务端事件流承载：打开会话先走一次历史批量 （GetHistory），随后 WatchEvents 续上直播——刷新页面、切走再切回都是同一条流。 用量轮次随会话续记，底栏仪表接着上次的账算。 侧栏 saved 区的快照则是跨进程的存档，恢复后继续可聊。

考核、门禁会不会在我不注意的时候卡死流程？

不会，设计原则是永不阻断：覆盖率门禁自身出错只记 gate skipped；闭卷考核异步执行，不打断正在进行的 prompt； 考挂只警告、照常入账。完全不想被自动考核打扰就设 LYON_EXAM=off（想连盲评也关就再设 LYON_SCORE=off）。

数据存在哪里？会不会上传到云？

全部在本地 $LYON_HOME（默认 ~/.lyon）： 会话草稿与快照、leaderboard、考核题库、routing 推荐表、workflow、记忆。 无遥测。只有显式配置了 LYON_SYNC_URL/TOKEN 才会同步记忆。

怎么接 OpenAI 兼容端点？

两种等价方式：设 ANTHROPIC_BASE_URL 指向兼容网关 （协议按 Anthropic Messages 解析），或用 -openai-base https://host/v1 / LYON_OPENAI_BASE 走内置的 OpenAI 协议翻译层。key 与官方一致复用即可； 也可以本地起一个录制/转换代理（ANTHROPIC_BASE_URL 指过去）。

打断之后为什么还能继续聊？

打断会触发历史修复：给悬空的 tool_use 合成一个 tool_result，让下一次请求合法。 这也是迭代预算到顶时的收尾机制——所以「停了」不等于「坏了」， 输入任何消息都能接着来。

7 ·开发者地图

读代码从这里进，完整版见仓库 README「架构」一节。

路径职责
cmd/lyondGo 守护进程：HTTP/SSE + Connect RPC（Session/Settings/Approval/File/Plan…）、准入控制、OpenAI 兼容网关；prompt_end 挂 evolve.Hook
web/React + Vite + connect-es 前端：SessionList 侧栏 / ChatView 转录与审批 / tiling 平铺面板 / MindMapCard / SettingsPane / EvolvePanel / Dashboard…
pkg/serverEvent Hub（seq 环、订阅重放）、connectRPC 服务实现、x-lyon-workspace 工作区头、审批与文件端点
pkg/agent引擎核心：Engine（连接池/并发信号量/预热）、Session（单驱动 goroutine + 事件流）、compact.go 客户端压缩、snapshot.go 会话存档、flow 工具
pkg/tools工具系统：run_shell / 文件读写（工作区禁闭）/ view_image / web_* / 记忆 / todo_write / prompt-cache 字节稳定化
pkg/evolve演化循环：评分入榜、闭卷考核、失败诊断——lyond 在 prompt_end 调它，所有入口共用
pkg/eval四维评分、leaderboard、闭卷考核题库、知识覆盖率、错因归纳
pkg/routing任务分类、开放度、推荐表（置信度 = mean×samples/(samples+3)）
pkg/models32 个模型的五维能力画像注册表
pkg/flow机械执行器：节点状态机、退出判据、有界重试、内置 4 条 workflow、门禁/诊断 glue
pkg/mindmap实时思维导图：蒸馏、事件、图编辑回流
pkg/mcp / pkg/memory / pkg/marketMCP 客户端 / 分层记忆 / 任务工时市场
internal/mockapi验收用假 API：真实 SSE 帧序 + prompt-cache 模拟器，测试全绿靠它
bench/性能验收套件（阈值强制）
docs/design/设计文档：agent-evolution.md 是演化机制的原始蓝图
跑一遍全量验收： go build ./... && go vet ./... && go test ./... -count=1； 前端类型检查 cd web && npx tsc -b。
